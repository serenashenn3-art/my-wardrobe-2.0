# 单品分类与搭配槽位

## 槽位(slot)定义

| slot | 中文 | 示例 | 一套搭配中的数量 |
|------|------|------|------------------|
| `top` | 上装 | T恤、衬衫、毛衣、卫衣、背心 | 1 件 |
| `outerwear` | 外套 | 西装、大衣、夹克、风衣、开衫 | 0–1 件(与 top 叠加) |
| `bottom` | 下装 | 裤、半裙、短裤 | 1 件(与 dress 互斥) |
| `dress` | 连衣裙 | 连衣裙、连体裤、套装 | 与 top+bottom 互斥 |
| `shoes` | 鞋 | 单鞋、运动鞋、靴、凉鞋 | 1 双 |
| `bag` | 包 | 手提、斜挎、双肩、手拿 | 0–1 个 |
| `hat` | 帽子 | 棒球帽、贝雷帽、渔夫帽 | 0–1 顶 |
| `jewelry` | 首饰 | 耳环、项链、戒指、手链、胸针 | 可多件 |
| `scarf` | 丝巾围巾 | 丝巾、围巾、领带 | 0–1 条 |
| `socks` | 袜子 | 中筒袜、船袜、丝袜 | 0–1 双 |
| `accessory` | 其他配饰 | 腰带、墨镜、手表、发饰 | 可多件 |

无法归类的单品用 `accessory`。

## 单品档案字段

录入每件单品时提取,用于标签与后续检索:

- `slot`:上表槽位
- `label`:品牌名;无品牌用「品类 + 颜色」(如「白色棉T恤」)
- `color`:主色(黑白灰/米/驼/蓝等,用于配色建议)
- `style`:风格关键词(通勤/休闲/运动/正式/街头等)
- `seasons`:季节数组,取值 `春` / `夏` / `秋` / `冬` / `四季`,一件可多季

季节判断经验:

| 单品特征 | seasons |
|----------|---------|
| 吊带、无袖、短裤、凉鞋 | `["夏"]` |
| 短袖/薄款连衣裙、雪纺 | `["春","夏"]` |
| 长袖连衣裙、衬衫、薄针织 | `["春","秋"]` |
| 贝雷帽/呢帽、厚外套、长靴 | `["秋","冬"]` 或 `["冬"]` |
| 首饰、包、四季鞋(乐福/运动)、棒球帽 | `["四季"]` |

衣橱展示按季节筛选时,`四季` 单品出现在每个季节页签下。

## 搭配完整性检查

生成卡片前对照:
- 核心三角:上装(or 连衣裙)+ 下装 + 鞋,缺一项时提示用户
- 同槽位冲突:两件上装、两双鞋等,请用户确认是否都要上卡
- 配色提醒:全身超过 3 个主色时给一句温和提示(不强制)

## 槽位冲突解决策略

搭配时可能出现同槽位多件或互斥槽位同时出现的情况,按以下策略处理:

### 互斥槽位冲突(dress vs top+bottom)

| 场景 | 处理方式 |
|------|----------|
| 用户同时选了 dress 和 top | 优先保留 dress, 提示「连衣裙已含上装, 是否移除多余上装?」 |
| 用户同时选了 dress 和 bottom | 优先保留 dress, 提示「连衣裙为整体造型, 是否移除多余下装?」 |
| 用户同时选了 dress + top + bottom | 保留 dress, 移除 top 和 bottom, 提示原因 |

### 同槽位多件冲突

| 槽位 | 多件策略 |
|------|----------|
| `top` | 保留最后选择的一件; 若是叠穿需求(如衬衫+卫衣), 用户需明确确认 |
| `shoes` | 保留最后选择的一双; 不允许两双鞋同时上卡 |
| `bag` | 保留最后选择的一个; 特殊造型需求(双包叠搭)需用户确认 |
| `bottom` | 保留最后选择的一件; 不允许两条裤子/裙同时上卡 |
| `jewelry` | 允许多件(可多件是槽位固有属性), 不视为冲突 |
| `accessory` | 允许多件, 不视为冲突 |
| `hat` | 保留最后选择的一顶; 不建议同场两顶帽 |
| `scarf` | 保留最后选择的一条 |
| `socks` | 保留最后选择的一双 |

### 冲突处理流程

1. **检测**: 在用户确认搭配前, 扫描已选单品的 slot 列表
2. **互斥冲突**: 立即提示并给出推荐方案(保留哪个、移除哪个)
3. **同槽冲突**: 提示「检测到同槽位多件, 默认保留最后选择的 [label], 是否保留全部?」
4. **用户确认**: 冲突解决后才进入搭配卡生成流程
5. **Web 应用**: 搭配卡画布上添加第二件同槽位单品时, 弹出确认提示
